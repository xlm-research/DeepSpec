# Loop/mHC 草稿训练使用执行层边界特征与独立最终状态

Loop/mHC 的物理层会重复执行，循环内部残差又包含四条流；以普通物理层号或未说明归一化位置的“最后特征”定义训练输入，会使草稿和后续恢复无法确定实际语义。DSpark 训练选择零基执行层 3、27、51、75、78 的自然 4096 维输出作为五个条件特征，并将真正进入目标 LM head 的 post-norm 最终状态独立传输。该契约沿用目标本身的 mHC 轮次收敛，保留现有草稿输入形状，也避免训练侧重建或重复应用目标 final norm。

## Considered Options

- 从循环内部均匀采样并压缩四流表示：需要额外定义归约或投影语义，会改变草稿的条件输入；首版选择目标已有的自然边界。
- 最终执行层同时充当第五个辅助特征和 verifier 状态：现有槽位角色会发生去重或碰撞；选择倒数第二执行层作为第五个辅助点，最终状态单独表示。
- 传 pre-norm 最终状态并在训练端重建 Gemma norm：可以正确实现，但需要保证架构构造、权重加一和精度语义；V2 已提供真实 post-norm 输出，因此选择直接消费该输出。

## Consequences

模型辅助采集槽为 4、28、52、76、79；存储 manifest 另设最终逻辑槽 80。后端和 connector 必须显式理解 80 个执行层，而原 checkpoint 保留 32 个物理层的权重定义。辅助列表不携带 final 槽，训练端不再次归一化最终目标状态。

采集点、顺序、最终状态角色及归一化位置构成训练缓存和草稿 checkpoint 的兼容性约定。变更这些语义时必须核查已有产物，不能仅因张量形状相同便恢复使用。参数共享和推理历史隔离继续沿用既有 Loop 设计。

本记录确认设计取舍，不表示代码已实现或 GPU 验收通过。验收合同见[训练规格](../qwen3_5_loop_mhc_dspark_spec.md)，决策来源见[设计问答](../qwen3_5_loop_mhc_dspark_plan.md)。
