# Qwen3.5 Loop + mHC 单机八卡 DSpark 训练规格

状态：实现完成，AC-01 至 AC-08 已通过；真实训练、完整恢复、满 128K 更新及 TP=8 回归见[验收汇总](../examples/qwen3.5-loop-mhc-dspark/verification.json)。记录日期：2026-10-10。

后续变更：用户要求草稿 attention heads 与 head dimension 对齐目标 full attention，现设为 Q heads 16、KV heads 4、head dimension 256。上述 GPU 验收使用旧的 32/8/128 结构，不覆盖本次结构变更；旧草稿 checkpoint 不能直接用于新结构的完整恢复。

## Problem Statement

用户希望参考现有 Qwen3.8-27B 单节点训练流程，使用 vLLM 为 Qwen3.5 Loop + mHC 提供目标模型前向与隐状态采集，在同一台八卡机器上训练配套 DSpark 草稿模型。训练数据为用户指定的 20 条对话，要求支持 128K 上下文并产出可恢复的训练 checkpoint。

实施前，Loop + mHC 已完成 TP=8 的目标推理接入，但未接通此训练链路。参考训练流程依赖 V1 的隐状态提取方式；Loop 既有运行基线使用 V2，并且缺少训练需要的辅助表示输出。Loop 的 32 个物理层展开为 80 个执行层，循环内部还存在四流残差，因此参考模型的采集层号、5120 宽度草稿及最终状态约定不能直接复用。

本需求训练的是 DSpark 草稿。目标模型及训练侧使用的目标 embedding、LM head 保持冻结；vLLM 在本阶段负责目标前向和训练特征采集。

## Solution

在单机八张 H800 上，以四卡 TP=4 的 vLLM V2 目标引擎和四卡 FSDP 草稿训练组成完整链路。使用已有回答监督，完整对话作为上下文，仅最后一轮 assistant 回答参与 loss；采用五个明确的执行层边界作为草稿条件特征，并以目标模型真实的最终归一化后状态计算目标分布。

草稿采用五层、4096 隐藏宽度的 DSpark，从头初始化可训练参数。指定 20 条有效样本按全局 batch=4 完成一轮五次 optimizer 更新，保存完整 checkpoint，并验证恢复后继续更新。

128K 指 131072 tokens 的模型总长度上限。采集请求为内部生成预留一个 token，因此训练样本输入最多 131071 tokens。除指定数据训练外，独立验收满长样本的分块采集、传输、草稿前向、反向和参数更新。

交付包含专用配置、启动及恢复用法、dry-run 与配置查看能力，以及实际运行报告。本阶段不设草稿推测解码部署、接受率或加速比门槛。

## User Stories

1. 作为模型使用者，我希望沿用现有 Loop + mHC checkpoint，以便直接使用已有目标权重训练草稿。
2. 作为模型使用者，我希望只更新 DSpark 草稿的可训练参数，以便保持目标模型行为和原始权重不变。
3. 作为训练使用者，我希望一次训练在单台八卡机器上完成，以便使用当前计算资源复现结果。
4. 作为训练使用者，我希望四卡运行目标推理、四卡运行草稿训练，以便在同一流程中完成采集和更新。
5. 作为模型维护者，我希望新增 TP=4 支持有实际运行证据，以便明确它与既有 TP=8 能力的验证范围。
6. 作为训练使用者，我希望直接读取指定的 20 条对话，以便用已准备的数据完成接入验收。
7. 作为训练使用者，我希望完整对话保留为上下文，以便最后一轮回答仍能依赖早先轮次。
8. 作为训练使用者，我希望明确只监督最后一轮 assistant 回答，以便监督范围不随内容检测隐式变化。
9. 作为训练使用者，我希望有效样本和监督 token 数得到核对，以便发现截断、过滤或 mask 错误。
10. 作为训练使用者，我希望目标模型对已有回答进行前向计算，以便保留数据集原有监督内容。
11. 作为训练使用者，我希望内部用于完成请求的额外 token 不进入训练监督，以便输入与原始 loss mask 保持对应。
12. 作为长上下文使用者，我希望请求总长度支持 131072 tokens，以便训练接近 128K 的样本。
13. 作为长上下文使用者，我希望分块 prefill 保留各执行层的完整历史，以便长输入无需缩短上下文。
14. 作为模型维护者，我希望物理层参数继续共享、执行层状态继续独立，以便 Loop 语义保持一致。
15. 作为草稿训练使用者，我希望特征包含循环前、三轮循环末和后段表示，以便草稿能接收不同执行阶段的信息。
16. 作为模型维护者，我希望特征以执行层和循环轮次解释，以便重复执行的物理层不会被误认为同一个采集位置。
17. 作为草稿训练使用者，我希望五个条件特征具有一致宽度，以便复用现有 DSpark 条件输入接口。
18. 作为模型维护者，我希望最终目标状态与草稿条件特征有独立角色，以便最终状态不会被去重或错误混入条件输入。
19. 作为训练使用者，我希望目标最终状态只经历正确的一次归一化，以便 DSpark 蒸馏使用真实目标分布。
20. 作为训练使用者，我希望目标特征按原 token 位置传输，以便多块输入完成后仍能正确对齐监督。
21. 作为训练使用者，我希望非法采集层、重复角色或错误形状明确失败，以便不会静默使用不完整特征训练。
22. 作为草稿训练使用者，我希望使用尺寸适配目标的五层 DSpark，以便目标 embedding、LM head 和草稿输出能够配合。
23. 作为草稿训练使用者，我希望从头初始化草稿可训练参数，以便不依赖不兼容的既有草稿权重。
24. 作为草稿训练使用者，我希望保留 CE、L1 和 confidence 训练项，以便完整接通现有 DSpark 训练目标。
25. 作为训练使用者，我希望指定 20 条样本完整参与一轮训练，以便验收不会因 batch 向下取整而遗漏尾部样本。
26. 作为训练使用者，我希望看到实际五次 optimizer 更新，以便区分成功初始化和真正完成训练。
27. 作为训练使用者，我希望 loss、梯度和模型状态保持有限，以便发现训练中的非法数值。
28. 作为训练使用者，我希望观察到草稿参数更新和目标参数冻结，以便确认优化边界符合需求。
29. 作为训练使用者，我希望 checkpoint 保存 optimizer、scheduler 和步数等完整状态，以便可以继续已有训练。
30. 作为训练使用者，我希望恢复后再完成一次有效更新，以便验证恢复功能不止于读取文件。
31. 作为训练使用者，我希望恢复与原运行使用不同输出目录，以便保留两次运行的证据和产物。
32. 作为训练使用者，我希望采集语义和目标身份随运行记录保存，以便识别不兼容的缓存或 checkpoint。
33. 作为资源使用者，我希望采集并发、预取和样本池匹配长样本容量，以便避免缓冲不足或无法凑齐训练批次。
34. 作为资源使用者，我希望请求和训练正常结束后释放资源，以便后续运行可以继续使用同一台机器。
35. 作为训练使用者，我希望先查看实际解析配置和启动命令，以便在启动 GPU 工作前核对输入与资源分配。
36. 作为维护者，我希望原有目标推理和其他训练采集模式通过相关回归，以便新路径不会破坏已有能力。
37. 作为长上下文使用者，我希望独立验证满 128K 的训练更新，以便较短真实数据的成功不会掩盖长度限制。
38. 作为数据所有者，我希望长度压力用例使用独立数据，以便原始 20 条对话保持不变。
39. 作为验收者，我希望运行报告记录实际长度、更新步数和 checkpoint，以便复核完成情况。
40. 作为验收者，我希望结构检查、训练运行和模型效果的结论明确区分，以便不会把训练接通当成加速或质量提升的证明。

## Implementation Decisions

1. **接入边界。** 复用现有 TorchSpec 训练入口、DSpark trainer、FSDP、数据调度及 Mooncake 传输。修改范围集中于 Loop 辅助表示输出、目标后端采集选择、执行层元数据、传输角色及相应配置。新增专用训练示例，目标推理示例继续承担原有用途。

2. **目标身份与模型语义。** 使用现有 ckpt-225-bf16 目标，保留其原架构声明和 32 个物理层配置。物理层 4–27 重复三轮形成 80 个执行层；沿用共享物理参数、独立执行层状态及逐轮 mHC 展开和收敛的既有约定。

3. **单机拓扑。** 一个目标引擎采用 TP=4、PP=1、DP=1，使用四张 H800；其余四张用于 FSDP 草稿训练。扩展并验证 Loop 的 TP=4 支持，保留既有 TP=8 推理能力。其他并行拓扑继续遵循既有支持限制。

4. **目标运行基线。** 使用 vLLM V2、eager、BF16 主干、FP32 mHC router 和 FP32 SSM 状态。启用分块 prefill，单步 token 预算 8192，最多一个请求，关闭 prefix caching。分块前后沿用同一请求各执行层的历史。

5. **监督与采集解耦。** 训练保持已有回答监督模式，目标引擎通过 V2 直接采集接口取得表示。采集不依赖 speculative proposer；目标引擎不加载训练中的 DSpark，也不接收其权重同步。保持原 loss mask 的数据路径，不切换到重新生成回答并重建 mask 的流程。

6. **五个草稿条件特征。** 选择零基执行层 3、27、51、75、78 的输出，分别对应循环前、三轮 mHC 收敛后及倒数第二执行层。每个位置自然输出宽度 4096 的表示；不额外引入循环内部四流压缩或可学习投影来改变采集语义。

7. **层号与角色契约。** 模型辅助采集槽依次为 4、28、52、76、79，最终目标状态使用独立逻辑槽 80。目标后端和传输端显式使用 80 个执行层的元数据；checkpoint 的物理层数仅表达权重归属。五个辅助槽与最终状态角色分别处理，层号越界、角色重复或数量不一致应明确失败。

8. **最终目标状态。** Loop 向采集接口返回五份辅助特征，另提供实际进入目标 LM head 的 post-norm 最终状态。最终槽 80 不加入模型的五项辅助采集表。训练声明最终状态已经归一化，跳过目标 final norm 的重建和重复应用；草稿自己的 final norm 与 Markov head 沿用现有语义。

9. **传输合同。** 对 L 个原始输入 token，五份条件特征按既定顺序合并为 L 行、每行 20480 维；最终状态为 L 行、每行 4096 维，token 和 loss mask 均长 L。分块结果按绝对 token 位置合并。发布结果必须覆盖原输入完整有效范围，内部新增 token 不进入训练样本。

10. **数据与监督轮次。** 使用指定的 20 条 conversations 数据，沿用 qwen 对话模板；完整对话作为上下文，显式选择最后一轮 assistant 回答监督。最少监督长度为 14 tokens，当前文件全部满足。预处理、采集及训练之间保留这一 mask，任何实际截断或过滤均计入运行记录。

11. **长度边界。** 训练配置与目标引擎的总长度上限均为 131072。已有回答 prefill 预留一个内部生成 token，将输入限制为最多 131071；额外 token 只用于请求完成。超限输入按已有预处理和请求校验规则处理，实际训练长度不得超出有效限制。

12. **草稿结构。** 采用五层 DSpark，hidden size 4096、MLP 宽度 8192、query heads 16、KV heads 4、head dimension 256、词表 248320、Markov rank 256。头数和 head dimension 与目标 full attention 对齐；草稿仍采用 DSpark backbone。草稿可训练参数从头初始化；目标 embedding 和 LM head 从目标 checkpoint 加载并冻结。既有 MTP 或不同隐藏宽度的草稿不属于本次初始化来源。

13. **训练目标。** 沿用 DSpark 的七 token block、512 anchors、位置衰减参数 4.0，以及 CE 权重 0.1、L1 权重 0.9、confidence 权重 1.0。教师分布由正确对齐的最终目标状态和冻结 LM head 计算；保留现有 next-token 对齐及 Markov 预测约定。

14. **训练规模。** FSDP 使用完整分片与 gradient checkpointing；microbatch=1、梯度累积=1，全局 batch=4。20 条有效数据一轮形成五次 optimizer 更新。学习率为 1e-4、最大梯度范数 0.5、warmup 比例 0、seed=42；该轮学习率总步数为 5。

15. **资源缓冲。** 初始推理并发为一，预取深度为一，样本池至少容纳一次四样本训练派发。按字节核查 host、Mooncake 及训练 fetch 的容量；每条满长样本六份 BF16 表示约 6 GiB，还需考虑 TP rank 副本和临时复制。容量调整服务于确认的单机训练目标，不附带吞吐指标。

16. **保存与恢复。** 保存完整模型、optimizer、scheduler、RNG 和 global step；在第 2、4 步及轮末保存，并保留最近两份。独立恢复验收从第 4 步继续至第 5 步，使用新的输出目录和相同目标、特征及草稿契约。沿用现有异步数据队列的 best-effort 恢复范围，不承诺逐样本或逐位等价重放。

17. **产物兼容性。** 记录目标身份、草稿配置、五个执行层采集点、最终状态归一化位置及数据监督策略。恢复或读取缓存时按这些语义核对兼容性；不同语义不得被视为同一份训练状态。

18. **启动与可观测性。** 提供一条可复用启动路径，以及 dry-run、解析配置查看和完整恢复方式。日志和运行报告记录实际有效配置、样本与监督数量、分项 loss、更新步数、资源情况、checkpoint 和异常。目标前向完成或草稿构建成功不等于训练验收通过。

## Testing Decisions

1. **沿用已确认的主验收边界。** 以现有 TorchSpec 训练入口及其可观察结果为主要边界，覆盖 vLLM 目标采集、Mooncake、FSDP 更新和 checkpoint。完整方案已经包含这条链路，本次规格整理不新增测试入口或扩大验收范围。

2. **测试行为合同。** 检查输入、配置、输出角色、token 对齐、更新与恢复等行为。测试不绑定私有函数名、内部调用次数、精确生成文本或特定张量存储地址。对采集位置和归一化语义的检查应证明消费端收到正确表示，而不是只证明配置中写入了层号。

3. **在现有边界定位错误。** 配置与传输合同使用现有的配置解析、后端输出和 connector 接口检查；DSpark 损失及冻结行为复用既有模型训练用例。主运行验收使用真实目标 checkpoint 和确认的八卡拓扑，CPU 协议检查不能替代 GPU 训练结果。

4. **复用已有先例。** 现有目标后端用例覆盖无草稿采集配置及状态元数据，Mooncake 用例覆盖请求结束、发布和对齐，DSpark 用例覆盖分项损失与梯度，GPU smoke 检查真实 optimizer step 和有限 loss。已有 Loop 生成验证可用于受影响的目标模型行为回归。

5. **必须完成的验收。**

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 配置与启动预览 | dry-run 和解析配置明确显示正确目标、指定数据、4+4 拓扑、草稿结构、末轮回答监督及 128K；无需启动训练即可核对 |
| AC-02 | 采集协议及负例 | 五个辅助执行层、独立 final 和 post-norm 语义一致；无越界静默过滤、角色碰撞或重复归一化；错误层号、数量、形状得到可解释错误 |
| AC-03 | TP=4 真实目标采集 | 原权重加载成功，短输入与跨 prefill 分块的输入完成采集；原 token、mask 与六份表示按位置和行数对齐，表示数值有限 |
| AC-04 | 指定 20 条训练 | 全部有效样本在未中断的一轮中进入训练，实际完成五次更新；CE、L1、confidence、总 loss 和梯度有限，草稿可训练参数更新，目标及冻结权重保持不变 |
| AC-05 | 完整保存与恢复 | 第 4 步和轮末 checkpoint 完整；独立运行加载第 4 步模型、optimizer、scheduler/global step 等状态后继续到第 5 步，并发生有效更新 |
| AC-06 | 满 128K 训练链路 | 独立有效样本达到 131071 输入加内部一个 token，包含足够连续监督；完成分块采集、Mooncake 传输和草稿前向、反向、实际更新，无 OOM 或挂起 |
| AC-07 | 状态复用及收尾 | 连续样本和长样本后的请求正常工作；请求、训练和相关资源正常完成或释放，后续运行可继续启动 |
| AC-08 | 受影响功能回归 | 既有 TP=8 目标推理、标准模型及参考采集模式的相关检查通过；新增路径不改变其他模式的合同 |

6. **覆盖真实长度与满长边界。** 已有 CPU 分词证据显示 20 条输入长 7177–105647，均未截断。AC-04 覆盖真实数据；AC-06 使用独立数据达到 128K 边界，并组成四卡训练能够实际派发的完整 batch。长度检查不改写用户原始数据，也不以单纯成功推理替代反向和更新。

7. **更新、恢复与样本覆盖证据。** 保存分项指标、有限梯度及草稿参数变化证据，记录进入训练的样本标识或等价覆盖信息。未中断的一轮应覆盖 20 条样本；恢复验收验证完整状态加载和后续更新，不将异步队列 best-effort 行为表述为精确重放。五个步骤的 loss 无需单调下降。

8. **证据边界。** 记录实际配置、输入与监督 token 数、分块及传输结果、训练步数、checkpoint 和异常。保留主机及设备资源记录用于复现，但不设置额外性能门槛。源码推导、CPU 数据检查和既有 TP=8 推理结果均不能代替本次 TP=4、训练或 128K GPU 验收。

## Out of Scope

- 目标模型本体微调、联合训练，以及更新目标 embedding 或 LM head。
- 在线重新生成回答作为监督，或将全部 assistant 轮次改为本次默认监督。
