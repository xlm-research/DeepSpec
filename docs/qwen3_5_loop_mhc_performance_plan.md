“精度不要改变”是已确认约束，但用户没有明确选择逐位一致或接受某个误差阈值；上表零差异门槛是本方案提出的保守验收办法，待整体确认，并非承诺尚未实现的融合一定能做到。数值测试通过只证明覆盖用例，不证明对所有输入逐位一致。

实施顺序如下：

1. **基线与归因。** 固定源代码、权重、输入、有效配置及精度设置，完成无 profiler 的 TTFT 基线；另开诊断运行，区分 mHC、attention/GDN、投影、通信与调度开销。现有 Python 栈比例不用于代替 GPU 时间占比。
2. **局部融合。** 优先验证 mHC 投影后的 FP32 log-Sinkhorn 融合，保留完整 20 轮、行列归一化顺序和原 FP32 投影。根据实际热点再评估 RMS、四流聚合与回写。保留原路径用于对照和回退，不直接套用公式不同的通用 mHC kernel。
3. **正确性与接入。** 先核查原路径自身的可重复性，再对照融合前后算子边界输出；回归目标 logits、五份特征、独立最终状态、128K 分块续接和原监督 mask。禁止量化、降低中间计算精度、减少迭代或改变矩阵方向；数值门槛未满足的候选不启用。
4. **重复测速与交付。** 在同一配置下重复 128K 单输出 TTFT，报告时间变化、加速比、显存、冷启动以及所有失败或回退候选。小形状和分块边界用于正确性检查，不再把 8K/32K/64K 多档速度列为主验收。

实现、测速入口及结果记录围绕本地 vLLM 交付；性能脚本进入合适的 benchmark/example 目录，正确性检查复用邻近测试。当前阶段不包含 DSpark 推测解码，也不把换权重、改分块预算或换精度造成的差异算作融合收益。

| --- | --- |

### 保持精度的融合候选

依据 [QwenLoop router 与残差实现](../vllm/vllm/model_executor/models/qwen3_5_loop.py)，首个候选是 router 投影之后的系数处理与 log-Sinkhorn：保持 FP32，逐轮先行后列 `logsumexp` 归一化，完整执行 20 轮，最后取指数。可把多次小矩阵操作放在融合 kernel 内，减少启动与中间张量读写；它是否主导当前 TTFT、实际能带来多少收益，需要 GPU 分阶段测量。

后续候选为输入 BF16→FP32 与 RMS 归一化、四流聚合和残差回写。初期可保留原 FP32 `F.linear`，缩小改动及数值验证范围。融合必须保留已有系数转型和 BF16 matmul、乘法、加法的舍入边界；不能将中间步骤悄悄全改为 FP32 后仅在末尾转 BF16，也不能将原 FP32 投影替换为降低有效计算精度的路径。

库内 [通用 mHC 参考](../vllm/vllm/model_executor/kernels/mhc/torch.py) 使用不同的归一化顺序、普通域 Sinkhorn 与 epsilon，混合矩阵方向及转型边界也不同；[TileLang 实现](../vllm/vllm/model_executor/kernels/mhc/tilelang.py) 另含 TF32 GEMM 路径。因此它们仅作实现参考，不能当作本模型可直接替换的等价算子。

现有 [采集契约测试](../tests/test_loop_capture.py)可复用，但使用假层，不证明 router 数值一致。[通用 mHC 测试](../vllm/tests/kernels/test_mhc_kernels.py)可参考组织方式，不能直接复用其不同公式的参考输出和误差阈值。本次未运行或编写 GPU kernel；融合工具、具体边界与误差阈值均尚未完成验收。

## 已确认的目标与约束

提高本地 vLLM 对 Qwen3.5 Loop/mHC 的独立回答生成速度。必须支持三轮 Loop、四条 mHC 流、20 轮 Sinkhorn、128K 上下文上限，并保留现有五份辅助特征、独立 post-norm 最终状态、已有回答及最后一轮回答监督语义。128K 沿用领域定义，为输入与输出合计上限。

不要求绑定最初的 ckpt-225-bf16；每组实现优化的前后对照应使用同一份权重。推荐先使用现成权重建立基线，优化实现不写死其权重值；不同结构的全面泛化尚未列为交付要求。禁止量化及其他计算精度改动，保留 BF16 主干与 FP32 router/SSM，以及原有中间精度转换。Q10 再次要求精度不变，没有明确接受浮点误差阈值；具体保守验收办法列入完整方案。

验收先建立同硬件、同输入、同测量口径的可复现基线，再报告实际性能收益及显存开销，区分冷启动和稳态，不预设加速倍数。主负载已固定为 131071 输入 + 1 输出，TTFT 为主指标；计时起止的具体执行口径列入完整方案。生成方式为目标模型自身的自回归生成，本阶段不接入 DSpark 推测解码。

用户确认当前训练环境为单机八卡，并选择独立推理 TP=8。已有单机训练示例采用四卡 FSDP 加四卡 TP=4 目标模型；历史日志可证明这种分配运行过，不能据此认定用户当前任务仍采用它。TP=8 的回答确定了模型分片，没有授权停止现有训练。建议在八卡空闲的独占窗口执行性能对照，实际运行前核对资源状态并安排窗口。

事实依据：[单机训练配置](../examples/qwen3.5-loop-mhc-dspark/config.yaml)、[单机历史日志](../running_logs/qwen3.5-loop-mhc-dspark_20261010_233132.log)、[独立生成配置](../vllm/examples/qwen3.5-loop-mhc/config.yaml)。独立生成入口支持通过 `--model` 更换权重；旧功能验收的计时含诊断开销且负载不同，只用作线索，后续重新建立基线。
