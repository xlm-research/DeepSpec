# 22: 减少阶段保存与恢复开销

**What to build:** 训练操作者能够降低每次 draft 阶段保存和恢复的重复工作，并了解合法编译缓存与分区大小的实际收益；每阶段仍同步提交完整状态，随后完整卸载。

验收以母规格《保持 DSpark 训练语义的 TorchTitan draft 并行适配与阶段卸载》及 ADR-0001/0002/0003 为准，保留现有 DSpark 训练语义、draft/target 边界和运行环境。

**Blocked by:** 08：完成八卡真实 Qwen 128K 首阶段验收。

**Status:** ready-for-agent

- [ ] 以票 08 的分项性能基线选择候选，分别评估被 DCP 覆盖的重复权重初始化/读取、CPU 配置与固定拓扑描述复用、checkpoint 数据路径、合法 compile 缓存和按完整 update 调整分区大小。
- [ ] 恢复优化仍重建必要 GPU 模型与 optimizer 对象并完整填充状态，包含 frozen 参数、FP32 master weights、Adam moments/计数、scheduler 和进度；复用对象不能持有旧 GPU Parameter、通信或预取缓冲引用。
- [ ] 在构建和加载完成后、下一 draft forward 前恢复训练 RNG；改变初始化随机消耗或 target 阶段不会改变后续 anchors、样本顺序和更新结果。
- [ ] 编译候选只用于已合法的模型/拓扑组合，分别记录首次编译、重建后的实际缓存命中及加载成本；保留 native ring CP 与外层 compile 的限制，不能把理论缓存支持当作实测收益。
- [ ] 分区大小调整只改变完整 updates 如何划入阶段，保持样本顺序、逻辑 microbatch、GAS、update 分组及 epoch 截断；固定训练工作量比较阶段数量变化的时间和资源成本。
- [ ] 所有候选保持完整 DCP 同步提交后才卸载和进入 target 阶段、最近两份保留及按需 HF 导出；若评估异步保存 API，实际等待完成的成本仍计入保存，不能假定隐藏了全部保存时间。
- [ ] 拟采用优化通过真实模型连续训练与跨阶段恢复对照，覆盖不等分母、GAS 不小于 2、至少两次 updates、新进程恢复、真实提交故障和多阶段 GPU 状态释放。
- [ ] 报告训练/保存/卸载/恢复分项与总耗时、首次及后续阶段成本、CPU/GPU 内存、I/O 和重复测量波动；排除 target 生产及等待，实际 HF 导出按频率计入保存，只采用数值正确且有收益的候选。
- [ ] 记录无收益或不兼容候选及其原因，现有 target 环境和推理行为保持不变，最终选定优化与后续并行布局的组合由票 23 验收。
