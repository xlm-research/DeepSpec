# 07: 滚动保留 checkpoint，并按需导出 HF 权重

**What to build:** 训练操作者能够在存储受控的情况下保有最近两份完整阶段恢复点，同时为评估或最终交付获取可用 HF 权重，显式保留的产物不会被滚动清理。

验收以母规格《保持 DSpark 训练语义的 TorchTitan draft 并行适配与阶段卸载》及 ADR-0001/0002/0003 为准，保留现有 DSpark 训练语义、draft/target 边界和运行环境。

**Blocked by:** 05：阶段 checkpoint 支持 DCP 独立提交与重启恢复。

**Status:** ready-for-agent

- [ ] 只有新阶段 checkpoint 成功提交并验证后才执行滚动清理，连续至少三次提交后保留最近两份完整阶段 checkpoint，且最新恢复入口仍有效。
- [ ] 显式里程碑和最终产物按独立保留规则受到保护，不因普通阶段 checkpoint 滚动而被删除。
- [ ] 新保存失败或存在未提交目录时，不删除上一成功恢复点；清理结果不影响最近完整 checkpoint 的实际可恢复性。
- [ ] 普通阶段只保存完整 DCP 与必要元数据；评估或最终交付需要时才导出 HF/safetensors，并记录实际导出频率。
- [ ] 导出的 HF 权重能通过现有模型消费/评估路径加载，模型身份、配置、必要 frozen 权重及输出与对应 DCP 一致；恢复训练仍以完整 DCP 为依据。
- [ ] 通过训练入口验证两份保留 checkpoint 的恢复能力、里程碑保护和按需导出，使用真实文件提交与清理场景；HF 导出失败不使已成功提交的 DCP 失效。
- [ ] 实际发生的 HF 导出耗时计入 draft 保存成本，不能将其遗漏或视为每阶段必需。
